# goal_planning routing — design

**Date:** 2026-05-01
**Status:** Design
**Owner:** Amoul

## Summary

The intent classifier defines `goal_planning` as a first-class intent, but no goal-planning agent module exists today. The router at `app/services/chat_core/brain.py:124` silently bundles `goal_planning` with `asset_allocation` and dispatches both to the asset_allocation chat handler. As a result, a pure feasibility question like *"I want to retire in 15 years with ₹5 crore — is that possible?"* is answered with an allocation recommendation, which is the wrong shape of answer: the user asked whether a target is achievable, and we returned a portfolio mix instead of feasibility math we can't yet do.

The canned `GOAL_PLANNING_MESSAGE` in `AI_Agents/src/intent_classifier/prompts.py` is generated by the classifier (`classifier.py:122`) but ignored by the router — dead code that suggests behavior the system doesn't have.

This spec routes `goal_planning` to a dedicated branch that returns an honest, reworded redirect message until the real goal_planning agent module is built. It also tightens the classifier prompt boundary between `goal_planning` and `asset_allocation` so the routing signal is reliable, and adds a small eval set to lock in the boundary.

## Goals

- Stop returning allocation output for pure feasibility questions.
- Make `GOAL_PLANNING_MESSAGE` actually reach the user, with copy that's honest about the gap and useful in the meantime.
- Tighten the classifier so the `goal_planning` vs `asset_allocation` decision is predictable for boundary cases.
- Preserve the `goal_planning` intent end-to-end so that when the real module ships later, it's a single router-branch swap with no classifier or prompt churn.

## Non-goals

- Building the goal_planning agent module itself (feasibility math, required-SIP calculation, glide-path). That is a separate spec when prioritised.
- Any changes to `stock_advice`, `portfolio_query`, `general_market_query`, `rebalancing`, or `out_of_scope` routing.
- UI changes in the chat surface.
- Persisting goal definitions or syncing with the Profile section's goals model.

## Locked design decisions

| Decision | Choice | Why |
|---|---|---|
| `goal_planning` in classifier | Keep | Honest labeller; one-line router swap when the real module ships |
| Today's behavior | Dedicated router branch returns the canned redirect | Pure feasibility questions deserve a feasibility-shaped answer; allocation is the wrong shape |
| Canned-message reach | Use `classification.out_of_scope_message` already attached at `classifier.py:122` | The plumbing already exists; just consume it |
| Boundary policy | Personal-money hook → `asset_allocation`; pure feasibility / required-savings → `goal_planning` | Predictable, matches what each branch can actually answer |
| Eval set | Small (10–20 cases) covering boundary phrasings | Detects classifier drift when prompts are tuned |
| Dead code | `GOAL_PLANNING_MESSAGE` stays (now used); existing test at `test_intent_classifier.py:174` stays valid | Keeping the constant means the future router swap is the only delta |

## Changes

### 1. Router fix — `app/services/chat_core/brain.py`

Today, `brain.py:124` reads:

```python
if intent_value in ("asset_allocation", "goal_planning"):
    ...
    result = await dispatch_chat(intent_value, turn_context)
    return await finalize(result.text, ...)
```

Replace with two separate branches. `asset_allocation` keeps its current behavior. `goal_planning` returns the canned message attached by the classifier:

```python
if intent_value == "asset_allocation":
    ...
    result = await dispatch_chat(intent_value, turn_context)
    return await finalize(result.text, ...)

if intent_value == "goal_planning":
    flow.append("goal_planning → canned redirect (module not yet built)")
    trace_line("next module: goal_planning → canned redirect")
    return await finalize(classification.out_of_scope_message)
```

Telemetry should record this as a real `goal_planning` turn (not as `asset_allocation`) so usage of the intent is visible and motivates building the module later.

### 2. Reword `GOAL_PLANNING_MESSAGE` — `AI_Agents/src/intent_classifier/prompts.py`

Replace the current copy:

> *"Goal planning is coming soon to Prozpr! In the meantime, please head over to your Profile section and update your financial goals there — that way we'll have everything ready to give you a personalised plan the moment the feature goes live."*

The new wording must:

- Acknowledge the gap honestly (we can't yet do feasibility math / required-SIP calculation).
- Be useful in the meantime — invite the user to ask an allocation-shaped question if they have money in hand or a portfolio context. Example pivot phrasing: *"If you'd like, tell me how much you can invest each month and I can suggest an allocation that fits a 15-year horizon."*
- Stay short (3–5 sentences).
- Avoid promising a delivery date.
- Avoid sending the user to the Profile section as a workaround unless that flow actually serves the question (today it doesn't).

Exact wording is finalised during implementation; this spec only fixes the requirements above.

The `STOCK_ADVICE_MESSAGE` and `OUT_OF_SCOPE_MESSAGE` constants are not in scope for this change.

### 3. Tighten classifier prompt boundary — `AI_Agents/src/intent_classifier/prompts.py`

The current `goal_planning` definition (prompts.py:30–42) and `asset_allocation` definition (prompts.py:9–27) overlap on questions that contain both a goal and a personal-money hook. Disambiguate by formalising the rule:

- **`goal_planning`** triggers when the *primary* ask is feasibility, achievability, or required-savings math — questions whose natural answer is a number or a yes/no about whether a target is reachable.
  - "Can I retire with ₹5cr in 15 years?"
  - "How much should I save each month for my daughter's college in 10 years?"
  - "Will my current SIP be enough to hit ₹2cr by 2040?"
- **`asset_allocation`** triggers when the *primary* ask is where to put money — including when a goal is mentioned as context, as long as the question shape is "where should I invest". A goal mention alone does not flip the intent.
  - "I have ₹50k/month and want ₹10cr in 15 years — where should I invest?" → `asset_allocation`
  - "Should I add midcap to my portfolio for my retirement goal?" → `asset_allocation`
- **Tie-breaker:** if a question has both a personal-money hook *and* a clear feasibility ask ("at ₹50k/month, can I hit ₹10cr in 15 years, and where should I invest?"), classify as `goal_planning` — the feasibility component is the part we cannot answer well, and the user is better served by the honest redirect than by a partial allocation that ignores the feasibility question.

Update the prompt's example list and the "Classification Rules" section accordingly. Keep the existing follow-up logic unchanged.

### 4. Boundary eval set — `AI_Agents/tests/test_intent_classifier.py` (or a new test file)

Add a parametrised test covering 10–20 cases on the goal_planning vs asset_allocation boundary. Cases should include:

- Pure feasibility questions, no money hook → expect `goal_planning`.
- Money-in-hand with a goal mention → expect `asset_allocation`.
- Required-savings questions ("how much should I save monthly for X?") → expect `goal_planning`.
- "Where should I invest" with no goal → expect `asset_allocation`.
- Combined feasibility + allocation ask → expect `goal_planning` (per the tie-breaker).
- A few adversarial phrasings that swap money/goal positioning to surface ordering bias.

The test runs against the live classifier (Claude Haiku). Acceptance threshold and whether to make it a CI gate vs. a periodic check are decided in the implementation plan.

## Architecture overview

```
User question
      │
      ▼
intent_classifier (Haiku)
      │  (tightened prompt; goal_planning vs asset_allocation boundary made explicit)
      ▼
ClassificationResult { intent, out_of_scope_message, ... }
      │
      ▼
brain.run_turn  (router)
   ├── asset_allocation → dispatch_chat("asset_allocation", ...)   [unchanged]
   ├── goal_planning    → finalize(classification.out_of_scope_message)   [NEW branch]
   ├── rebalancing      → dispatch_chat("rebalancing", ...)        [unchanged]
   ├── portfolio_query  → generate_portfolio_query_response(...)   [unchanged]
   ├── general_market_query → market commentary path               [unchanged]
   ├── stock_advice / out_of_scope → finalize(canned message)      [unchanged]
```

When the real goal_planning module ships, the only change at this layer is replacing the `goal_planning` branch with a `dispatch_chat("goal_planning", ...)` call. No classifier or prompt changes are required at that point.

## Risks and mitigations

| Risk | Mitigation |
|---|---|
| Classifier under-fires `goal_planning` after the prompt tightening, sending feasibility questions to `asset_allocation` (current bug persists) | Boundary eval set; review failures before merge |
| Classifier over-fires `goal_planning`, sending genuine allocation questions to the redirect | Eval set covers money-in-hand cases; tie-breaker rule is asymmetric (combined → goal_planning) by design and accepted as a tradeoff |
| Reworded message confuses users who previously saw the "Profile" pivot | Acceptable — the prior copy was misleading anyway; new copy offers a more useful pivot |
| Telemetry on `goal_planning` shows zero usage and the intent looks dead | This is the intended visibility — concrete usage data should drive whether/when to build the module |

## Open questions

- Should low-confidence `goal_planning` (e.g. confidence < 0.6) fall back to `asset_allocation`, or always redirect? Default in this spec: always redirect; revisit if the eval set shows confidence-correlated errors.
- Should the redirect message vary based on whether the user has a portfolio loaded vs. an empty portfolio? Default: single static message; personalisation can be a follow-up.

## Out of scope

- The future goal_planning agent module (feasibility engine, required-SIP solver, glide-path). Separate spec.
- Persisting goal definitions or integrating with the Profile section's goals model.
- Changes to other classified-but-redirected intents (`stock_advice`, `out_of_scope`).
