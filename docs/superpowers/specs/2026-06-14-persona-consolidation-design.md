# Persona Consolidation — Design Spec

- **Date:** 2026-06-14
- **Status:** Draft for review
- **Owner:** Ask PI backend

## Problem

Customer-facing prose is generated by ~12 independent prompts spread across `app/domains/*` and
`AI_Agents/src/*`. They have drifted apart:

- **Persona name varies:** "PI" (most), "Prozpr" (`asset_allocation/services/aa_engine/service.py:400`),
  "financial planning analyst" (`AI_Agents/src/cashflow_statement/summarizer.py:31`), unnamed
  (`AI_Agents/src/asset_allocation_pydantic/steps/_rationale_llm.py:90`), and a **stale "Tilly"**
  still live in `app/domains/intent_classifier/services/intent_classifier_engine.py:38` and visibly
  leaking in the latest `chat_eval` report.
- **Contradictory format/money rules:** the house style says copy the pre-formatted `_indian` money
  string verbatim (`answer_formatter/formatter.py:58`); the AA composer says use "L"/"Cr"
  (`aa_engine/service.py:420`). Markdown/emoji conventions exist only in the house style and nowhere else.
- **Question-acknowledgment is actively forbidden** on two high-traffic paths:
  `general_chat_engine.py:127` ("no acknowledgment, no reference to prior turns") and
  `aa_engine/service.py:421` ("no echoing the question, no greeting").

Only **3 of ~12 surfaces** share the good house style (`FORMATTER_HOUSE_STYLE`,
`answer_formatter/formatter.py:48`); the rest each re-derive a voice. Net effect: inconsistent voice
across the product, and answers that don't situate themselves in the customer's question.

## Goals

1. **One shared voice/identity** for every customer-facing surface — name, reader definition, tone,
   money rules, jargon glossary, risk-category naming, disclaimer.
2. **Format scales to the artifact** via a small set of format profiles (one voice, *not* one format).
3. **Question-awareness:** remove the anti-acknowledgment bans and add a brief restate-the-question
   opening — directly fixes the "doesn't add the context of the question" complaint.
4. **Kill the live bugs:** the "Tilly" leak, the "Prozpr" name drift, the money-format contradiction.
5. **Before/after eval** so we can see how answers actually change.

## Non-goals

- A full automated LLM-judge presentation rubric (deferred — out of scope for this pass).
- Rewriting the numeric engines / pipelines.
- Changing routing / intent-classification logic.

## The voice model: one voice, format scales to artifact

**One shared core, identical everywhere:** `PI_IDENTITY` + `SHARED_MECHANICS` + `QUESTION_OPENING`
+ `DISCLAIMER`. Same name, reader, tone, money rules, jargon glossary in every surface.

**Format profiles** select only the *allowed formatting vocabulary*, chosen by where the text is
displayed:

| Profile | Container | Formatting allowed |
|---|---|---|
| `chat` | a standalone chat bubble | full markdown — tables, emoji, headings, bold, blockquotes |
| `plain` | a field embedded inside a larger structure | prose + inline bold only; **no** tables/emoji/headings |
| `document` | the monthly market-commentary artifact | full vocabulary + long-form sectioning + letterhead/disclaimer |

**Why `plain` is justified (not arbitrary):** two surfaces emit text that is embedded inside a bigger
structured object, where block-level markdown would break the layout:

- `AI_Agents/src/asset_allocation_pydantic/steps/_rationale_llm.py:105-107` —
  `RationaleResponse.goal_rationales` is a `Dict[str, Dict[str, str]]` of short per-goal strings,
  attached to the plan and rendered by `step7_presentation.py`.
- `AI_Agents/src/risk_profiling/prompts.py:13` — `RiskProfileSummary.summary`, a single 4-5 sentence
  paragraph rendered in a profile card.

Centralizing "prose only, no block markdown" into `plain` beats copy-pasting that rule into each body
prompt. **Decision point for review:** keep three profiles (recommended) or collapse to `chat` +
`document` and push a one-line "prose only" into the two embedded bodies.

## Architecture

- **New `AI_Agents/src/persona.py`** — single source of truth. Self-contained, stdlib-only (same
  constraints as `AI_Agents/src/common.py`); must not import any peer agent module.
- **Re-exported via `app/domains/ai_engine/persona.py`** — mirrors the proven `common.py` re-export
  pattern (`app/domains/ai_engine/common.py:23`). This is the only home importable by **both** layers
  without violating the layering rule (AI_Agents/src never imports from app).

### Public API

```python
# AI_Agents/src/persona.py
PI_IDENTITY: str        # name "PI", org (Prozpr, SEBI-registered), reader (retail Indian investor,
                        # may have no finance background), friendly-friend voice, what-to-avoid
SHARED_MECHANICS: str   # money (_indian verbatim, never million/billion), jargon glossary,
                        # asset-class labels, risk-category naming
QUESTION_OPENING: str   # "Open by briefly restating, in your own words, what the customer asked,
                        # then answer it."
DISCLAIMER: str         # "general information, not personalized advice"
FORMAT_PROFILES: dict[str, str]   # {"chat": ..., "plain": ..., "document": ...}

def build_system_prompt(body: str, *, format_profile: str = "chat") -> str:
    # PI_IDENTITY + SHARED_MECHANICS + QUESTION_OPENING + FORMAT_PROFILES[profile] + DISCLAIMER + body
```

- `answer_formatter` rebuilds `FORMATTER_HOUSE_STYLE = build_system_prompt("", format_profile="chat")`
  and keeps it exported as a **backward-compatible alias**, so existing tests
  (`answer_formatter/tests/test_formatter.py:30,51`) stay green. `assemble_prompt`
  (`formatter.py:107`) calls the builder.
- **Prompt caching:** the system prompt is already sent with `cache_control: ephemeral`
  (`formatter.py:174`). A stable shared preamble improves cache-hit rate; centralizing does not hurt it.

## Testing

### Before/after snapshot harness (the key addition)

Reuse `AI_Agents/src/chat_eval/` (`run_eval.py` runs questions through `ChatBrain.run_turn`;
`build_html.py` renders). Extend, do not rebuild.

1. **Curate 15-20 questions** (new `questions_voice.yaml` or a tagged subset of `questions.yaml`)
   covering every touched surface **and** the specific behaviors changed:
   - asset_allocation: a first-plan request; a follow-up "why so much equity?" (question-awareness)
   - portfolio_query: a holdings question; a market + portfolio-impact question
   - general_chat: a factual lookup (e.g. repo rate); a conceptual question
   - rebalancing; goal_planning; risk profiling; market commentary
   - canned paths: an `out_of_scope` question; a `stock_advice` question (these surface the "Tilly" leak)
2. **Fixtures:** a fixed test profile + fixed/empty history; pin `market_commentary_latest.md` so
   market answers are comparable across runs.
3. **Step 0 — freeze the baseline BEFORE any code change.** Run the set on current code, save an
   immutable `baseline_2026-06-14.json` + rendered HTML. Time-critical: cannot be reconstructed once
   prompts change.
4. **After all changes:** re-run the identical set, render a **two-column before/after HTML** (extend
   `build_html.py`) for human review of voice / format / question-awareness.
5. **Determinism control:** temperature 0 for eval runs; fixed question set + fixtures. Note: Haiku at
   temp 0 is near- but not fully deterministic, so the diff is human-judgment input, not an
   exact-match assertion.
6. **Optional cheap flags** on the "after" column to make regressions pop: contains "Tilly"? contains
   "million"/"billion"? opens by restating the question?

Expectation: because the voice change is intentional, the diff **will** show large text changes
everywhere. The review judges whether they are improvements, not whether they differ.

### Unit tests

- `persona.py`: `build_system_prompt` includes the PI identity + money rule for each profile; never
  contains "Tilly"; the `plain` profile excludes table/emoji/heading guidance.
- Per migrated surface: assert the surface's assembled system prompt contains the shared PI identity
  marker.
- Existing engine + `answer_formatter` tests remain green.

## Risks / open questions

- **Market commentary tone shift:** moving from formal CFP/HNI register to PI's friendly voice is a
  product decision (you chose "one voice everywhere"). Confirm against the rendered `document` sample
  in the before/after review.
- **`plain` profile:** recommended; trivially collapsible to two profiles if preferred (see voice-model
  section).
- **Determinism:** the before/after diff includes some sampling noise; mitigated by temp 0 + fixed
  fixtures, but not eliminated.
